### Achado 1 — os calculadores não mostram o resultado 🔴

**Onde:** `frontend/src/components/redesign/ModuleView.tsx:495`

O renderizador genérico de `type: "form"` faz:

```ts
setMsg({ ok: d.ok !== false, text: d.message || scr.submit.okMsg || 'Concluído.' });
```

Mostra a mensagem e **descarta o corpo da resposta**. Existe um gancho para documentos
(`d.doc`, linha 498) e nenhum para resultado.

**O que se perde.** `POST /calcular/simples` com receita 250.000 / RBT12 3.005.979,80 devolve:

```json
{ "valor_das": 42050.83, "aliquota_efetiva": "16.82%", "anexo": "III",
  "distribuicao": { "irpj": 1682.03, "csll": 1471.78, "cofins": 5390.92,
                    "pis": 1169.01, "cpp": 18250.06, "iss": 14087.03 } }
```

Na tela: **"DAS calculado"**. Só isso.

**Reproduzir:** `/redesign/fiscal` → Calcular DAS → 250000 / 3005979.80 → Salvar.

**Impacto:** vale para os **5** calculadores. Uma calculadora que não mostra o número não
serve para nada — o backend está certo, o fio está ligado, e a tela é inútil assim mesmo.
É o caso mais puro de "API 200 ≠ entregue" que este projeto já produziu.

**Conserto recomendado (não feito — QA não conserta):** gancho aditivo análogo ao `d.doc`,
opt-in pelo builder (`submit.showResult`), renderizando os escalares do corpo num painel.
Sem flag, nada muda nos ~200 outros forms. É frontend puro: os endpoints já devolvem tudo.

### Não-achado — o 201 é cosmético

`calcular/simples` responde **201 Created** e não cria nada: `status_code=201` está fixo no
decorator, o handler não recebe `get_db` e chama uma função pura
(`fiscal_controller.py:1578`). Rótulo errado, comportamento certo. É endpoint clássico
compartilhado — **não mexer** (blindagem só no redesign).

### Não-achado — sidebar "fora da viewport"

O primeiro clique falhou por "element is outside of the viewport". Não é defeito: o `nav`
tem `overflow-y: auto` e rola. A viewport do Playwright estava com 493px de altura. Com
1440×900 o clique funciona.
