# F3 — a perna 2, medida antes de construir

## (a) O runtime aceita servidor MCP por sessão? **Não como configuração.**

`register_mcp_servers(servers)` em `/app/tools/mcp_tool.py:5162` é **global do processo**:
protegido por um `_lock` de módulo, idempotente **pelo NOME do servidor**, e as tools entram
num singleton — `registry = ToolRegistry()` (`tools/registry.py:765`), com prefixo
`mcp-<nome>`.

Os testes `test_load/resume/fork_session_registers_mcp` existem, mas registram os servidores
**do config** ao carregar a sessão; não é um servidor por usuário.

⭐ Consequência que decide: uma conexão por usuário significaria N servidores no MESMO
registro de processo. As tools do usuário A ficariam no mesmo espaço de nomes que as do B,
alcançáveis por qualquer conversa daquele processo. **Trocaríamos "sem identidade" por "a
identidade de todo mundo disponível para todo mundo"** — pior que hoje.

**Portanto: a perna 2 não é configuração. É fork ou shim — projeto.**

## (b) O que o Hermes com 4 tools IMPEDE que o `run_engine` já não faça

```
capacidades in-process (tools + sub-operações):  189
MCP servidas ao agente:                          146   (4 usáveis · 142 barradas)
barradas SEM equivalente in-process por nome:    112
```

Nome não é capacidade. Classificando as 112 por **classe**:

| classe | n | exemplos |
|---|---|---|
| editar registro existente | 4 | `atualizar_cliente`, `atualizar_contrato`, `atualizar_estagio_deal` |
| arquivar / excluir | 3 | `arquivar_contrato`, `arquivar_deal`, `excluir_proposta` |
| mover estágio / definir meta | 7 | `assumir_negociacao`, `definir_meta_contratos_mes` |
| baixar PDF pronto | 4 | `baixar_contrato_pdf`, `baixar_proposta_pdf` |
| consultor C-level | 11 | `cfo_panorama`, `cfo_perguntar`, `consultar_juridico` |
| outros | 83 | precisam de revisão caso a caso |

**A linha que decide:** o que o in-process concretamente NÃO faz é **editar e arquivar
registro que já existe** — ele cria, lê e gera documento, mas não tem `atualizar_*` nem
`arquivar_*` (14 tools somando as três primeiras classes). Exemplo concreto: pelo chat hoje o
Jordan cria um cliente e anota nele, mas **não corrige o CNPJ de um cliente já cadastrado**.

Os 83 "outros" eu **não** classifiquei — dizer que são duplicatas ou que são buracos, sem
abrir um a um, seria a suposição que este dia inteiro provou cara.

## Recomendação

A perna 2 vira **projeto** (fork/shim), e o que ela desbloqueia é sobretudo *editar/arquivar* —
que também pode ser resolvido registrando ~14 tools in-process, onde a identidade já é real,
sem tocar em binário de terceiro. **O Jordan decide com o número: 14 tools in-process contra
um fork do runtime.**
