# Fase 5.6b — Moonshot #2: Análise de Contrato (lean, reusa funções puras) — Design
**Data:** 2026-07-29 · Triagem ad29eb74. Ponytail.

## Achado
`ai/contract_analysis/` = mesma casca sync/async quebrada (não montar). MAS a lógica é REAL e pura: `clause_extractor.py` (regex cláusulas/datas/valores/CNPJ/CPF), `risk_analyzer.py` (risk scoring por regras), `compliance_checker.py` (LGPD/CCT). Sem LLM. Reusável como FUNÇÃO PURA.

## Objetivo (1 frase)
Analisar um contrato existente (tabela `contracts` / doc GED) reusando as funções puras → superfície READ-ONLY no módulo jurídico + consultor: cláusulas, risco, flags LGPD/CCT como HIPÓTESE p/ revisão humana. NUNCA altera o contrato, nunca age, nunca fabrica (só o que o regex extrai do texto real).

## Abordagem (molde lean do 5.6a)
- Serviço fino `analise_contrato.py` (async): recebe id/texto do contrato → chama as 3 funções puras (copiar/importar só a matemática, ignorar CRUD/models/controller quebrados) → devolve dict {clausulas, risco, compliance}.
- Rota READ-ONLY no controller jurídico EXISTENTE (`GET .../contratos/{id}/analise`), gated (jurídico/diretoria). NÃO criar CRUD novo.
- Injetar flags de risco/LGPD ALTOS no consultor jurídico + sino (propor→aprovar: flag → humano revisa). Rotulado hipótese.
- Reusar a skill `conecta-pro-skills:juridico` (Central de Contratos + playbook compliance).

## Invioláveis
READ-ONLY sobre contracts (nunca altera/assina/renova). Nunca fabricar (só extrai do texto real; ausente=vazio honesto). Jurídico read-only p/ agente. Flag=hipótese não fato. Gate jurídico/diretoria.

## Tasks (lean)

- BT2: superfície (consultor jurídico + sino p/ risco alto, rotulado hipótese) + oráculos (read-only, nunca-fabricar, RBAC) + mutação.
