# Fase 5.5 — Memória que Aprende (com Curator) — Design/Spec
**Data:** 2026-07-28 · Antecede: 5.4c (deployada). Discovery: subagente a576b080 (2026-07-28).
**Nota de nomenclatura:** "5.5" aqui = "memória que aprende" (roadmap [[project_fase5.3_proativo]]), NÃO o "5.5 Endurecimento+E2E" do doc antigo do Hermes.

## Achado central que redefine o objetivo
**O sistema JÁ APRENDE SOZINHO — sem nenhuma curadoria, groundedness ou audit.** Três write-backs automáticos existem HOJE em produção:
1. **`consultor_hub.aprender()`** (`consultor_hub.py:295-347`) — após CADA resposta dos 8 consultores, `gpt-4o-mini` destila 0-2 "fatos duráveis" → INSERT em `consultor_memorias` → **relido por TODOS os 8 consultores** rotulado *"MEMÓRIAS PERMANENTES (aprendidas com o gestor — respeite-as)"* (linha 199). Sem groundedness, sem audit, sem expiração. **Maior raio de envenenamento.**
2. **`registrar_feedback()`** (`consultor_hub.py:353-382`) — `correcao` de texto do gestor → memória permanente `fonte='feedback_gestor'` sem checagem; **endpoint `/ai/consultor/feedback` sem gate de diretoria** (`consultor_feedback_controller.py:27`, qualquer user ativo).
3. **`_update_contact_memory()`** (`agent_service.py:2338`) — `gpt-5.1` resume 12 msgs → `cwi_message_log direction='mem'`; sem groundedness (raio: 1 telefone).

Ou seja: a 5.5 NÃO é construir aprendizado do zero — é **colocar um CURATOR no caminho do aprendizado que já acontece cego**, fechando o risco de fabricação. É tanto feature quanto correção de segurança do princípio inviolável "nunca fabricar".

## Objetivo (uma frase)
Toda memória aprendida passa por um **Curator** (ancoragem + audit + confiança + expiração) ANTES de virar autoritativa; o que não puder ser ancorado vira PROPOSTA numa fila de revisão da diretoria (reusa o padrão propor→aprovar da 5.4) — nunca fabrica, Jordan segue fonte da verdade.

## Paredes reusáveis (discovery)
- `garantia/groundedness.verificar(resposta, fonte)->{ok,suspeitos}` (`groundedness.py:112`) — ancora NÚMEROS. Reusar direto p/ fatos numéricos.
- `agent_audit.registrar_acao_agente(...)` (`agent_audit.py:33`) — append-only em audit_logs. Reusar p/ trilha de todo write-back.
- Evals gate: `backend/evals/run_evals.py` + `backend/scripts/orq/test_oraculos_*.py` (padrão `sys.exit(!=0)` em falha crítica). Extensível como gate de aprendizado.
- Padrão propor→aprovar (5.4 [[project_fase5.4_acoes]]): base.propor + fila no sino RBAC.

## Arquitetura (Curator no caminho de todo write-back)
Um **`memoria_curator`** (novo, `modules/ai/conversation/services/garantia/` junto da garantia) — `curar(fato, *, origem, fonte, autor_role) -> dict {status, motivo}`:
- **Ancoragem numérica:** se o fato tem número → `groundedness.verificar(fato, fonte_da_conversa)`; número não-ancorado (suspeito) → NÃO auto-ativa.
- **Ancoragem de entidade:** entidades citadas (cliente/CNPJ/empregado) devem existir em `clients`/`employees` reais; entidade inventada → NÃO auto-ativa.
- **Confiança/proveniência:** grava `confidence` + `fonte` (llm_destilado | feedback_gestor | contact_summary) + `autor` + `created_at` + `expira_em` (decay: fato operacional expira; fato estrutural não).
- **Audit:** `agent_audit.registrar_acao_agente` a CADA gravação (o que aprendeu, quando, por qual modelo, veredito do curator).
- **Status (ciclo de vida):** `proposto` → (auto-`ativo` SÓ se ancorado numérica/entidade E confiança alta E autor confiável) OU `pendente_revisao` (fila diretoria) OU `rejeitado`. Só `ativo` entra no `contexto_compartilhado`.

## Componentes
1. **`consultor_memorias` ganha colunas** (migration aditiva): `status` (proposto|ativo|pendente_revisao|rejeitado, default 'pendente_revisao'), `confidence` float, `fonte` (já existe), `autor`, `curator_veredito` jsonb, `expira_em` timestamptz. `contexto_compartilhado` passa a filtrar `WHERE status='ativo' AND (expira_em IS NULL OR expira_em>now())` (hoje é `WHERE ativo`).
2. **Gate no `aprender()`:** antes do INSERT, chamar `memoria_curator.curar(...)`. Fato ancorado+alta-confiança → status 'ativo'; senão → 'pendente_revisao' (NÃO contamina os 8 consultores até diretoria aprovar). Mantém o INSERT (não perde o aprendizado), só muda o status.
3. **Gate no `registrar_feedback()`:** (a) **RBAC** — só diretoria (require_consultor_executivo) grava memória permanente via correção; (b) correção do gestor = fonte confiável → auto-'ativo' mas AINDA auditada + ancorada (correção com número fabricado é sinalizada).
4. **Fila de revisão (propor→aprovar de memória):** as `pendente_revisao` caem no sino da diretoria (reusa entrega 5.3/base.propor); diretoria aprova→'ativo' ou rejeita→'rejeitado'. Rota `POST /ai/consultor/memorias/{id}/aprovar|rejeitar` (diretoria).
5. **`_update_contact_memory` (WhatsApp):** passa pelo curator (versão leve — ancora entidade do CRM: nome/CNPJ do resumo tem que bater com lead/cliente real do telefone); resumo não-ancorado é gravado como 'observação não confirmada' (não citado como fato).
6. **`.md` humanos INTOCADOS** (consultor_conhecimento + agent_knowledge WhatsApp): a 5.5 NÃO escreve neles automaticamente (risco 4/5 da discovery). Promoção de memória→.md, se um dia, é manual pela diretoria (fora de escopo).
7. **Evals como gate de aprendizado:** `backend/scripts/orq/test_oraculos_5_5.py` — oráculos: (a) fato fabricado (número não-ancorado) NÃO vira 'ativo'; (b) entidade inventada NÃO vira 'ativo'; (c) contexto_compartilhado só lê 'ativo' não-expirado; (d) feedback de não-diretoria NÃO grava memória permanente; (e) todo write-back gera 1 linha de audit; (f) mutação: desligar o curator → oráculo (a) morde.

## Global Constraints (invioláveis)
- **NUNCA FABRICAR** — memória não-ancorada NÃO é autoritativa; vai pra revisão humana. Jordan=fonte da verdade.
- Não perder aprendizado real (grava sempre, muda só o status/autoridade).
- Não quebrar os consultores (contexto_compartilhado continua funcionando, só filtra 'ativo').
- Audit append-only de todo write-back. Expiração/decay p/ memória não virar lixo eterno.
- RBAC: memória permanente só diretoria (correção) ou curator-aprovado.
- Deploy blue-green; migration aditiva; bancada throwaway; git add próprios; commits --no-verify + Co-Authored-By; TZ Manaus. Peer-churn: commitar imediato.

O sistema já aprende cego; a 5.5 põe um Curator (ancoragem+audit+confiança+expiração) no caminho, memória não-ancorada vira proposta na fila da diretoria (propor→aprovar), e evals barram regressão — aprende sem nunca fabricar.
